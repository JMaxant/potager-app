# CI is one job whose steps run only when their inputs exist

The workflow in `.github/workflows/ci.yml` has a single job, `quality`, and every step that depends on something the repository does not have yet carries an `if: hashFiles(...)`: Postgres and migrations on `migrations/*.sql`, `task check:sqlc` on `sqlc.yaml`, `task check:templ` on `**/*.templ`. The workflow therefore does not have to be edited when the first migration, query or component lands: the step wakes up with its input. Conditioning a whole job was rejected: `hashFiles` needs a workspace, which does not exist when a job's `if` is evaluated, so the condition would have to be computed by another job; and every extra job pays for its own runner, checkout, Go setup and cache restore, far more than the few seconds saved by not starting Postgres. A step that is skipped shows grey, not green, so a green run does not prove that the database steps ran. Revisit with a separate integration job (and `services:` instead of Compose, which touches ADR 0006's single source for the Postgres version) once the integration tests are slow enough for running them in parallel with the lint to matter.
